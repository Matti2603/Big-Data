Testlauf

Parameter max_pages: z. B. 5 Seiten = 500 Karten statt aller 937

Task 2 · fetch_cards

Rohdaten unverändert sichern, schnell und robust

  • 6 Seiten parallel: 937 Seiten in unter 4 Minuten
  • Jede Seite als eigene Datei: raw/<Datum>/cards_page_0001.json
  • Vor dem Speichern prüfen: gültiges JSON mit Liste cards
  • Atomar schreiben: erst _tmp, dann umbenennen
  • _manifest.json: Zeitpunkt, Anzahl laut API, Seiten
SituationVerhalten
HTTP 429, 5xx, Netzfehlerbis 8 Versuche, Pause wächst bis 5 min, Retry-After
anderer Fehler (404)sofort abbrechen
Task bricht abAirflow-Retry macht bei der fehlenden Seite weiter
nach jeder Seite0,5 s Pause je Thread, API schonen
Task 3 · raw_to_final · PySpark

Aus 937 Seiten wird eine saubere Tabelle

  • Festes Schema beim Lesen, dann explode: eine Zeile je Karte
  • Ohne id oder name verwerfen, Duplikate nach id entfernen
  • Texte trimmen, leere Werte → NULL, multiverseid → Zahl
  • Bild-URLs auf https, Edition in Großbuchstaben
  • Deutsche Übersetzung als eigene Spalten (name_de, text_de …)
  • Spalten und Typen genau wie in ddl/final_cards.sql

Raw → Final

Größe beim ersten vollständigen Lauf

JSON, 937 Dateien: 366 MB

Parquet, 4 Dateien: 23 MB

Spaltenorientiert und komprimiert: rund 16× kleiner

Tasks 4 und 5

Für die Suche aufbereiten und sicher veröffentlichen

final_to_mongodb PySpark

  • Suchfelder normalisiert: klein, ohne Akzente, ß → ss
  • versions: Druckversionen je Name (Window-Funktion)
  • Farben auf Deutsch, Manakosten als Liste
  • Lädt in cards_staging mit Validator aus der DDL
  • Prüfung: Dokumente = Zeilen im Final-Layer

publish

  • Staging darf nicht leer sein
  • Vollständiger Lauf: höchstens 10 % weniger Karten als vorher
  • Indizes anlegen, dann renameCollection in einem Schritt
  • Die Suche sieht nie einen halb geladenen Stand
  • Datenstand in meta, angezeigt im Frontend

Frontend

Suche für Endnutzer

Funktionen

  • Suche in Name, Kartentext, Künstler oder allem
  • Teilstring, ohne Groß-/Kleinschreibung und Akzente: „weiss“ findet „Weiß“
  • Englisch und Deutsch: „Manta“ findet „Wolkenmanta“
  • „Jede Karte nur einmal“: Druckversionen per $group zusammenfassen
  • Detailseite mit Bildern und allen Druckversionen

Sicherheit

  • Eigener MongoDB-Benutzer nur mit Leserechten
  • Suchbegriff wird maskiert, höchstens 100 Zeichen
  • Ausgaben escaped, Content Security Policy
  • Alle Ports nur auf 127.0.0.1
  • Passwörter zufällig erzeugt, nicht im Repo

Fazit

Was das Projekt zeigt und was als Nächstes käme

Erreicht

  • Vollautomatischer, täglicher ETL-Lauf
  • Raw-Layer als originalgetreue Kopie, Neuverarbeitung ohne API
  • Suche bleibt bei Fehlern auf dem letzten guten Stand
  • Ein Befehl startet alles: make up

Ausblick

  • Spark auf einem eigenen Cluster statt lokal
  • Volltextsuche (z. B. Atlas Search) bei viel mehr Daten
  • Benachrichtigung, wenn ein Lauf fehlschlägt
  • Weitere Sprachen und Preise aus anderen Quellen
